# C7 v616: выпуск ускорения (результаты исполнения плана)

Дата: 01.11.2026. Базис: v615 (ZIP `b1fd9457…`). Всё headless; пайплайн штатный (lab → runtime bundle → next export → package → deploy). Цель: ускорить старт и кадр без изменения картинки; адаптивный DPR НЕ внедрялся (ждёт решения по требованиям).

## Что изменено в v616 (три правки)

1. **`lab/c7-scene/world.js` — солнечное квантование 1/256.** `renderState` квантизует solar до сетки 1/256 перед сравнением с `lastSolar`; travel (камера) остаётся непрерывным. PMREM/атлас/tree-shadows и `shadowMap.needsUpdate` пересоздаются только при переходе солнечной фазы через границу сетки, а не на каждый кадр. При медленной прокрутке это убирает реальную работу; при быстрой — обновлений не больше прежнего (механизм ниже). Конечные фазы (0 и 1) лежат на сетке — точны.
2. **Тот же файл — убраны per-texture yield'ы из цикла `initTexture`.** Вместо ~20 `setTimeout(0)` — одна пауза после цикла. Замер диагностики до/после: стадия upload 389 → 67 мс (mobile, M3 Pro); ~320 мс был чистый оверхед таймеров worker, не GPU.
3. **`app/c7/page.tsx` — `fetchPriority="low"` на 6 case-изображений** (desktop при холодном старте подтягивает их в окрестности вьюпорта). Приоритет изменён; на локальной сети без конкуренции время старта не сдвинулось (эффект — только на узких каналах; честно: на localhost выигрыша таймингов не видно).

## Инцидент деплоя и его разрешение (корень — .nojekyll)
Первые две попытки деплоя v616 сломали публичный сайт: HTML отдавался, а ВСЕ `/_next/static/*` отдавали 404. Причина — деплой-процедура `git rm -r .` удаляла файл **`.nojekyll`** из репозитория (он не входит в пакет), GitHub Pages включал Jekyll, который исключает из выгрузки каталоги с подчёркивания (`_next`). Диагностика: 404-probe по URL + проверка дерева коммита (файлы в коммите были, Jekyll их резал) + подтверждение `git ls-tree` (нет nojekyll в HEAD) → добавлен `.nojekyll` → чанки вернулись (200). Дополнительно: первая v616-сборка выполнялась с тёплым `.next` v615 (workspace-копия) и дала смешанные имена чанков; принято решение пересобрать начисто (workspace без `.next`, холодная сборка — `build-ws-v616-clean`), пакет пересобран, консистентность HTML↔файлы проверена. Публичный сервис во время инцидента был откачен на v615 (коммит 7913a1c), затем выкачена финальная v616.

# C7 — стоимость обновления окружения, v553

Диагностика в фоне, без агентов. Опубликованный код не меняется этой пробой.

## Основание

При изменении solar создаётся новая PMREM окружения размером 128. Из неё вода берёт восемь направлений с roughness 0,4, материалы деревьев — размытую небесную энергию. Видимое небо рисуется отдельно; отражение озера имеет собственный target. В профиле v467 environment-filter оказался дорогим, хотя абсолютные driver timers не равны времени кадра. Проверяется конкретная гипотеза уменьшения только промежуточной карты окружения до 64, без уменьшения main canvas или отражения.

API проверен по установленному Three r186, `node_modules/three/src/extras/PMREMGenerator.js`, и [официальной документации](https://threejs.org/docs/pages/PMREMGenerator.html). Навык: threejs-performance — измерять отдельно, не принимать догадку за ускорение.

## Проба и критерии

- B/C/C/B на 390×844 и 1440×900: 128/64/64/128, восемь секунд пролёта, первая секунда исключена. Страница создаётся заново для каждого варианта; время компиляции не входит в steady-state замер.
- Статические пары при travel 0/0,3/0,5/0,88/1, одинаковое время; сохранить полные PNG и пиксельные различия.
- При отсутствии устойчивого выигрыша отклонить. При видимых пятнах, изменении цветовых переходов, солнечной дорожки или крон — отклонить.
- При положительном результате провести полный цикл normal/low/390/1440/2560, reverse, restore и актуальную проверку страницы перед переносом.
- Техническая проба не закрывает физические устройства и не даёт 10/10.

Файлы: `evidence/c7-v553-environment-study/`.

## Результат v553

Различие десяти PNG-пар очень мало: среднее по каналу 0,0026–0,0124 /255, максимум 2, пикселей с отклонением более 2 нет. Однако выигрыш FPS невелик и близок к разбросу: 390 — 18,76→19,23 (+2,53%), 1440 — 9,59→9,95 (+3,77%). Снижение разрешения PMREM в продукт не перенесено.

Следующая диагностическая гипотеза v554: сохранить исходные 128 и все вычисления, повторно использовать один render target вместо удаления/создания при каждой фазе. Для фиксированного Three r186 проба перехватывает только `_allocateTargets` данного экземпляра PMREM; это внутренний API, требует строгой parity/lifecycle проверки перед любым переносом. Кроны не получают лишний needsUpdate, если envMap тот же объект. Метки 128/64 в диагностических именах означают исходное/повторное выделение; оба варианта имеют размер 128.

## v554 → кандидат v555

Повторное использование того же PMREM128 даёт пиксельно точные десять PNG-пар (max/mean 0). В парном замере 390: 17,78→19,95 FPS (+12,24%); 1440: 10,06→10,39 FPS (+3,33%). Это короткая лабораторная серия, не физическая приёмка.

В v555 адаптер ограничен Three.REVISION===186; при иной версии действует штатное выделение/освобождение. Удалено лишнее needsUpdate крон, когда объект envMap не менялся. Размер карты 128, её фильтрация и частота пересчёта сохранены. Внутренний метод `_allocateTargets` — осознанная зависимость от закреплённого r186, не универсальный публичный API.

Полная проверка 84 состояний (две версии × два качества × три размера × семь фаз) подтверждает 42 точных пары текущего/предыдущего мира, все reverse RGBA exact, shaders linked, ошибок нет. Восстановление WebGL на travel 0,3 возвращает точный кадр; double dispose — 0 геометрий, контекст освобождён, AbortError. Проверка многократного использования ресурсов выполняется отдельно.

Резерв: `backups/c7-v555-pre-environment-reuse-2026-10-28/`. Доказательства: `evidence/c7-v555-environment-parity/`, `evidence/c7-v555-lifecycle/`.

Ресурсная серия v555: 120 переходов normal/low, UUID окружения один на мир, версии материалов, число текстур и программ стабильны. Полный сайт на 2560 показал резкую просадку, которая воспроизводится и на v552, и без MSAA; до установления причины G07 остаётся FAIL. Новые доказательства не отменяются успешной parity.

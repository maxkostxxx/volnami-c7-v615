# C7 v615: освободить данные построения деревьев

v615 удаляет из живого runtime исходные JS-массивы и процедурный каркас деревьев после создания окончательной BufferGeometry. Картинка, число вершин, текстуры, разрешение, свет, отражение и путь камеры не упрощаются. Это правка постоянного расхода CPU-памяти, **не обещание ускорения GPU или мгновенной загрузки**.

## Что изменено

- `lab/c7-scene/tree-runtime.js:7`: локальный `RuntimeTree` вводит явный `releaseConstructionData()`. Сохраняются готовые типизированные геометрии, материалы и options; освобождаются только `branches`, `leaves`, `skeleton`.
- `lab/c7-scene/trees.js:715` и `:841`: opt-in выбирает этот класс и освобождает данные после изменения формы, расчёта bounds и фиксации stats каждого дерева. Обычный `Tree` остаётся поведением по умолчанию для прямых authoring-вызовов.
- `lab/c7-scene/world.js:166`: runtime включает opt-in. Изменение положения освобождения позволяет не удерживать данные всех13 деревьев во время последующего построения травы; реальный startup peak отдельно не измерен.

Getters количества вершин/треугольников после освобождения читают готовую геометрию. Повторное освобождение безопасно. `generate()`, `generateLODs()` и `createGeometry()` способны снова построить нужные данные. Прямой remesh из уже удалённых исходных массивов сообщает явную ошибку до dispose живой геометрии. Это контракт нового opt-in, не изменение обычного vendor Tree. Vendor, зависимости и общие настройки не правились.

Closure листового материала продолжает читать `options.leaves.roundedNormals`; options сохранены. CPU-атрибуты для context restore также сохранены. Новых render passes, ресурсов GPU, terrain/sky caches и отложенной подмены первого кадра не добавлено. Единственная новая работа — сброс трёх ссылок после построения каждого дерева и fallback getters при диагностическом обращении. GC не вызывается из продуктового кода.

## Основание и прототип

[L0/L1 аудит](c7-tree-construction-memory-v614-2026-10-31.md) объясняет владельцев, измерения и ошибки первых диагностических протоколов. В Node безопасный кандидат удалил86,01МиБ desktop и52,37МиБ mobile heap. В Chromium worker прототип удалил65,28МиБ desktop и38,09МиБ mobile. Это разные среды и метрики; одно число не заменяет другое.

Прототип: реальные13деревьев×2профиля дали точные атрибуты/индексы/bounds/matrices/stats/getters/material hooks. На всех26 проверены release/guards/regeneration/createGeometry, два claimed-handle abort сценария очищены один раз. Отдельные20fixed-pose captures точны. В8полносайтовых ABBA запусках изменения ready≈+0,4% и submitted throughput≈0…+0,3% не являются существенным ускорением.

Исходный combined quality gate прототипа оставлен **failed**: первый снимок после живого пролёта переводил wave clock назад без принудительного обновления reflection/PMREM. Он различался даже между baseline-повторами. Остальные32captures совпали. Отдельная проверка с полным восстановлением одинакового состояния дала20exact и закрыла именно этот вопрос. Число загруженных GPU geometries после rAF-пролёта варьировалось2015–2017 даже внутри baseline; это зависимость от посещённых участков, не измерение resident GPU. В новой методике отдельно фиксируются полное число geometry в scene, bytes атрибутов деревьев, textures/programs и статистика загруженных geometries.

## Ограничения и источники

G04/G07 — **REWORK**, G08 — **OPEN**. Функциональный Firefox не закрывает строгие cross-engine pixels; headless WebKit не заменяет native Safari. Физические iOS/Android, слабый GPU, VoiceOver/TalkBack, естественные GC-паузы, resident GPU peak, presented FPS и плавность на компьютере пользователя — **NOT_RUN**. Адаптивный DPR не реализован: отдельный вопрос требований ещё ожидает ответа. Новое существенное ускорение desktop-кадра остаётся недоказанным.

Точно прочитаны: текущие world.js, trees.js, vendor/ez-tree/tree.js и его PROVENANCE, cooperative-build.js; методы renderState/draw/setLight и sky.js для восстановления fixed-state; package-world/bundle-world/bake-mobile-profile/build-local/package-preview; CPU fixture I4, K0 instrumentation, K1 analyser, paced-servers, текущие manifests/checkpoints; установленные CDP definitions в Playwright.

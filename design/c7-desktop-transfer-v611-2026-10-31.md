# C7 v611 — компактные данные небосвода для desktop

Опубликован [v611](https://brave-cedar-204.harvis.page/c7/). Receipt до **01.11.2026 04:16:37 МСК**. HTTP200,83/83 SHA доставки и публичный пролёт/возврат390/1440/2560 проверены.

Сохраняются полный рельеф, плотность травы, геометрия и текстуры деревьев, 4k-облака, разрешение теней, DPR, отражение, траектория и солнечный цикл desktop. Меняется разрешение двух полей, описывающих закрытие небосвода рельефом: 512×256 → 256×128 и 256×128 → 128×64, по 17 слоёв. Это небольшое приближение освещения, не точное межверсионное совпадение desktop pixels.

Мобильная сцена уже использовала эти данные в v609/v610. Её качество этим шагом не уменьшается. Изменение применяется до ранней загрузки из v610; большие поля не скачиваются в обычном сайте.

Изначальная цель ускорения старта ≥15% **формально не пройдена**: результат ниже на 0.0334 процентного пункта. Тест не повторялся ради получения удобного процента. Решение продолжить принято по отдельному выполненному требованию пользователя — существенно уменьшить вес при малом изменении качества: передача меньше на 35.24%, изображение прошло строгий заранее заданный допуск. Не объявлять эту цель PASS округлением. Финальные проверки ниже нужны для проверки интеграции, а не для замены результата прототипа.

Данные о старте относятся к лабораторному runtime, а не к первому тексту, LCP или готовности полного сайта. Chromium153.0.8010.12, ANGLE Metal Apple M3 Pro, viewport1440×900, device DPR1, drawing buffer2160×1350; полный desktop-профиль. Настоящий HTTP, Brotli quality6 для текста, новый контекст, HTTP cache disabled, порядок B/C/C/B. Shader cache драйвера не очищался. Wave time10, одна и та же последовательность travel/solar; таймер старта начинается перед dynamic import. Раннее получение inputs включено с обеих сторон.

Packet test отдельно: 24 кадра прогрева, 3 пакета ×48 кадров на запуск, readPixels-барьер только на границах пакета, фиксированный прямой/обратный пролёт. Это завершение пакета GPU-работы, не реальные показанные кадры и не FPS телефона. Постоянный цикл, количество проходов и shader instructions от D3 не исчезают.

## Почему принят именно этот вариант

D1 одновременно уменьшал shadow maps и horizon fields. Он не прошёл визуальный порог: на travel0.08 2.9186% пикселей имели ошибку канала >16 при лимите1%. D2 оставил полные horizon fields, но уменьшил shadow maps — осталось2.8174%. Оба варианта отклонены **до** performance benchmark; проверки2560 для них не запускались.

D3 сохраняет исходные shadow maps4096/2048 и меняет только поля небосвода. Все16 фазовых сравнений1440/2560 прошли пороги MAE≤2/255 и доля ошибки>16≤1%. Dawn/noon на1440 и contact на2560 открыты непосредственно. Направления света, силуэты, форма берега и деревья сохранены. Утренний canopy fix предыдущих версий не откатывается.

## Конкретные изменения

- `lab/c7-scene/world.js`: отдельный `compactHorizon=true`, не связанный с плотностью/геометрией mobile. Он передаётся только загрузке и выборке полей. Диагностика сообщает `horizonQuality`.
- `sky-horizon.js`: параметр поля переименован из `mobile` в `compact`, потому что теперь применяется и на desktop. Сохраняются исходные направления, interpolation, fallback и число источников. Texel-clamp соответствует реальным размерам поля.
- `startup-inputs.js`: тот же выбор `compactHorizon` делается **до** world import. Каждый ответ забирается один раз. Worker/main fallback используют одинаковый default; отмена и очистка сохраняются.
- `app/c7/scene/shared-world.ts`, `render-worker.ts` и packaging scripts переключены на отдельный runtime-v611.

`compactHorizon:false` сохраняет возможность подготовить исходные поля; при внешней подготовке inputs этот параметр нужно одинаково передать helper и миру. Поэтому полный portable ZIP по-прежнему содержит обе пары. **ZIP не уменьшился на35%** — речь о реально запрашиваемых браузером данных. Историческая папка `mobile-data` содержит две теперь общие компактные карты; имя не определяет профиль остальных ресурсов.

Сжатые поля: 2 631 194 → 853 972 B, удаляется1 777 222 B обычной передачи. Их номинальные decoded HalfFloat arrays: 22 282 240 → 5 570 560 B. Это расчёт по размеру/формату двух текстур, не измеренный resident GPU peak и не экономия всей памяти приложения. Нового GPU-прохода, framebuffer, decoder или библиотеки не добавлено.

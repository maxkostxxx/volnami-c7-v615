# C7: решение этапа 3, 30.10.2026

Основной путь — убрать повторную подготовку статичного мира на устройстве посетителя, сохраняя тот же живой renderer. Для стоимости кадра — один ограниченный кандидат: вычислять гладкую атмосферную интеграцию земли на её существующей геометрии, сохраняя тени, BRDF, low-sky поля и отражение. Это две разные метрики; ускорение старта не выдаётся за ускорение кадра. Большой кадровый выигрыш пока не доказан, а полная замена освещения остаётся отдельной архитектурной задачей.

## Последовательность исполнения

1. **Инструмент.** Контроль завершения фиксированного пакета через readPixels в TypedArray на границах; новый script/названия метрик. Полный сайт остаётся отдельным rAF/active/suspended измерением. Устранение ошибки измерителя не требует переписывать старые результаты: добавить явное исправление их интерпретации.
2. **Точный shoreline алгоритм.** Пространственный индекс сегментов и row crossings вместо256distance tests для каждой из204800точек. Потребители — shoreDistance, terrain, lake и распределение травы. Новых HTTP-данных нет, добавится небольшой алгоритм. Условие: все Float32 значения побайтно одинаковы; средняя CPU длительность устойчиво ниже. Сначала isolated CPU probe, затем интеграция и provenance зависимостей.
3. **Атмосферное поле.** Сохранить тот же128²RGBA8+height range; удалить655360height lookups со старта. Потребитель существующий uC7SkyVisibility, без нового shader/pass/target. Budget ≤70KiB raw, точное сравнение каждого байта. Генератор остаётся для авторинга, runtime cache проверяет источник/размер/SHA/отмену. Ошибка не должна оставлять чужую или частичную текстуру.
4. **Placement cells дальней травы.** Сохранить только исходные x/z/Float64 weights в прежнем порядке; удалить статические ray sweeps видимости, оставить тот же RNG и генератор стеблей. Budget ≤200KiB compressed; если больше — не интегрировать. Сравнить все instance attributes, bounds, количество стеблей. Normal/low получают один общий небольшой placement field; не13MB baked blades.
5. **Первый экран и сборка.** Показать poster текущей первой камеры, пока готовится сложный мир; сделать правильные wide/portrait варианты. Разрешение placeholder — новая инструкция пользователя, поэтому прежняя политика пустой paper-поверхности больше не обязательна. Устранить только process-local ошибку проверочного tsconfig в evidence, затем проверить сохранённую правку «О нас». Не называть poster «живой сценой за0ms».
6. **Один кадровый кандидат.** Из ground fragment удалить12-sample optical integration; выполнять её на существующих terrain vertices и интерполировать два optical-depth значения (либо эквивалентные coefficients при проверке). Всё зависящее от текущей камеры/solar остаётся живым. Добавятся vertex ALU иvaryings, не новый FBO. Потребители — main/reflection ground draws; grass/trees сначала не затрагиваются, чтобы не умножить дорогой расчёт на миллионы их вершин. Это новая гипотеза, не повтор rejected horizon resolve/PCF skip/PMREM lookup. Пропуск sunset/mist, заморозка света и изменение карт не допускаются.
7. **Визуальные варианты.** Один фактор на вариант: нормали/контраст ближней травы; затем объём и полутона крон. Не увеличивать density по умолчанию. Сохранить центральный берегv599. Итог выбирается по полным кадрам и ROI в нескольких фазах, не по обещанию «идеального совпадения».

## Приёмка и остановка кандидата

Точные изменения старта: хэши полей/instance attributes, paired raw pixels, lifecycle/abort/restore и холодная сеть. Новый runtime не должен случайно смешиваться с v601: отдельный URL, source manifest, package verification. Работа только в разрешённых каталогах, checkpoints до каждого принятого изменения.

Атмосферный кандидат аппроксимирует пространственную нелинейную функцию, поэтому strict exact не предполагается. Начальный quality gate: на1440 в11фиксированных фазах/time10 mean RGB≤0,15/255, доля RGBdiff>5≤0,1%, отсутствие структурных швов и новых ореолов в terrain/reflection ROI; отдельные пики на antialiased edges объяснить, не скрывать. Порог — предварительный инженерный фильтр, не универсальный стандарт качества. Если gate не выполнен, не улучшать скорость ценой заметной картинки. Затем390/2560, reverse, отдельные движущиеся кадры. Скорость: ABBA/BAAB или достаточный повтор при разбросе, одинаковые SHA/backend/buffer/фазы/прогрев; ≥8% медианное улучшение завершённого пакета и согласованное направление full-site, без ухудшения старта/памяти. Если эффект в шуме — отклонить.

Если кадровый кандидат отклонён, это не завершение цели. Записать причину и заново выбрать следующий узкий вопрос на основании обновлённого профиля, не перебирать20старых идей. При ошибке диагностики исправить диагностику. При внешнем ограничении продолжать независимую работу. Не отправлять фиктивные сообщения от имени пользователя.

Оценка порядка: точные startup изменения и проверка — несколько часов; UI/poster/build — около часа при нормальной сборке; кадровый go/no-go —30–90мин; полная визуальная/браузерная приёмка принятых изменений — ещё несколько часов. Это рабочие оценки, не обещание сроков или кратности выигрыша.

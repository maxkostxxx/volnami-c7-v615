# v604: проверка последовательности загрузки

## Наблюдение и решение

Два новых одиночных запуска 1440×900/DPR1, Chromium 153/ANGLE Metal, normal drawing buffer 2160×1350. Изменения ответов JS только добавляли метки времени; продуктовые файлы не менялись. Локальный и публичный запуск — **не парное сравнение версий** и не FPS-тест.

| Событие от начала навигации | Локальный пакет | Публичная v604 |
| --- | ---: | ---: |
| Первый contentful paint | 140 мс | 728 мс |
| Завершение import(world) | 983 мс | 2097 мс |
| Завершение двух horizon-запросов | 1001 мс | 2390 мс |
| Потребитель запрашивает horizon | 2935 мс | 4893 мс |
| Ожидание claim | <0,1 мс | 0,1 мс |
| Готовность живой сцены | 3607 мс | 5608 мс |

**Ранний перенос horizon перед import(world) отклонён без реализации.** В обоих наблюдениях передача уже перекрыта остальной работой. Дополнительный владелец ресурсов и более длительное удержание 2,63 МБ сжатых данных здесь не дают выигрыша. На существенно более медленной сети ситуация может отличаться; это не измерено.

В публичном наблюдении обнаружена другая конкретная цепочка: `grass.js` 3569–3642мс, `grass-static.js` 4314–4391, `terrain-chunks.js` 4642–4716, `direct-zero-guard.js` 4785–4892, `compact-grass-shadows.js` 5177–5250. Сумма длительностей запросов около 405мс. Каждый нужен до первого кадра, каждый поздний import ожидается последовательно. Это наблюдаемые сетевые интервалы, **не гарантированные 405мс возможного ускорения**: изменение графа может переносить расходы в раннюю загрузку.

Проверены верхние уровни пяти модулей: объявления функций, строк GLSL, констант и одного WeakSet; создание геометрии/GL-ресурсов происходит внутри вызовов. Раннее связывание не требует раннего создания сцены. MDN рекомендует статический импорт для начальных зависимостей; при этом его побочные эффекты исполняются до тела импортирующего модуля, что требует данной проверки. [import()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import), [модули и порядок исполнения](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules).

Следующий ограниченный кандидат: заменить эти пять поздних импортов статическими в world/grass. Внешний import(world) в worker остаётся после проверки capability. Не добавлять preload в document, новый loader, worker, кэш или fetch. В лабораторном `noGrass` теперь будут загружаться определения grass, хотя трава не создаётся; это допустимый диагностический расход, но его нужно явно учесть.

Прочитаны текущие worker-entry/world/sky-horizon, верхнеуровневые зависимости grass/grass-static/terrain-chunks/direct-zero-guard/compact-grass-shadows, package-world, full-site-paired, сервер и прежние записи v600/ночного аудита об этих модулях. Новые результаты: `evidence/c7-overnight-2026-10-30/network-observation/results.json` и `network-observation-public/results.json`; SHA инструментированных файлов сохранены там. Публичная доступность перед проверкой: HTTP200. Новые GPU-проверки выполнялись последовательно; собственный сервер закрыт.

## Принятый кандидат

До опыта сохранён `static-import-plan.md`. Кандидат меняет только два авторских файла: верхние импорты и удаление пяти поздних `await import`. Код вызываемых функций, параметры сцены, геометрия, шейдеры, данные кэшей и декодирование не менялись. Разница текстового runtime −32байта. Все50 resource entries worker сохранены, суммарные encodedBodySize в локальном тесте 6602566→6602534байта. Это сумма запросов данного worker, включая проверочный повтор terrain.js; не ZIP, не весь сайт и не HTTP-трафик публичного хостинга.

| Новый ABBA, готовность DOM `.is-ready` | baseline v604 | кандидат | Вывод |
| --- | --- | --- | --- |
| Локальный HTTP | 3437,7 / 3442,0мс | 3450,2 / 3497,3мс | Среднее3439,85→3473,75мс; +0,99%, выигрыша нет, в пределах заранее заданного допуска3% |
| Каждый runtime JS имеет задержку ответа100мс | 4676,8 / 4705,1мс | 4134,1 / 4190,3мс | Среднее4690,95→4162,2мс; −528,75мс/11,27%. Обе пары быстрее; выполнены пороги8% и300мс |

Все восемь запусков последовательны, Chromium153/ANGLE Metal Apple M3 Pro, свежий context,1440×900/DPR1/normal2160×1350, без прогрева стартового сценария. Метрики относятся к подготовке первого кадра. Искусственная задержка моделирует **latency каждого JS**, не пропускную способность или конкретное подключение. Частота реальных показанных кадров и ускорение GPU здесь не измерялись. Не сравнивать абсолютные цифры с другими сессиями как версионную регрессию.

В delayed-кандидате пять ресурсов начинают передачу на110–227мс worker clock и заканчивают к332–338мс; в baseline последние запросы заканчиваются к4104–4143мс. Работа перенесена в начальный граф, а сеть/парсинг не исчезли. GPU-проходов не добавлено и не удалено.

Приёмка до переноса в продукт:

- 46/46 межверсионных raw-pixel пар точны: Chromium1440(22),390/2560(12), Firefox390(6), WebKit390(6). Фазы0…1 вперёд/назад, фиксированное wave time10. Совпадение внутри одного движка не является cross-browser pixel PASS.
- Восемь проверок полного сайта: непрозрачные sections/menu, manual pause, simulated hidden, noWorker fallback, noWebGL poster, уход на case во время подготовки — PASS.
- Три дополнительные проверки:503 обязательного модуля→видимый poster/0workers; уход во время задержанного import→0workers/0errors; context restore→точный кадр/GL0, повторный dispose→0geometries.
- Пакет кандидата отличался от baseline только world.js,grass.js,package.json. Перед продвижением сохранён checkpoint-v604 восьми файлов. Старый опубликованный runtime-v604 сверён и не изменён. Кэши не пересоздавались.

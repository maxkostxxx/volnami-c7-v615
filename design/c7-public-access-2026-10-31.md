# C7: доступ по публичной ссылке, 31.10.2026

Запрос: сохранить тот же адрес и обеспечить доступ посетителям с других IP. Точный адрес, которым пользуются посетители, и текст ошибки запрошены; ответа пока нет. Проверены два последних адреса — v614, ранее переданный пользователю, и v615, опубликованный до этого запроса.

## Подтверждено

В 13:12–13:15 МСК v614 и v615 доступны без cookies, аккаунта или заголовков авторизации. HTML, полученный локально через адрес из публичного DNS, побайтно совпадает с соответствующим проверенным пакетом.

| Адрес | Москва AS14576 | Москва AS210644 | Франкфурт AS34549 | Лос-Анджелес AS18978 |
|---|---:|---:|---:|---:|
| [v614, прежняя ссылка](https://lively-tundra-561.harvis.page/c7/) | 200 | 200 | 200 | 200 |
| [v615](https://spry-satchel-143.harvis.page/c7/) | 200 | 200 | 200 | 200 |

Внешние проверки: [v614](https://check-host.net/check-report/54a9b036k5d8), [v615](https://check-host.net/check-report/54a9b030k297). Это HTTP-проверка с четырёх сетей, не доказательство загрузки всех ресурсов, WebGL или доступности у каждого провайдера. Новые GPU/браузерные проверки в этом расследовании не запускались. Ранее выполненные публичные Chromium-проверки v615 имеют собственное время 08:11 МСК и не выдаются за проверки из этих четырёх сетей.

В текущем локальном подключении стандартный DNS не разрешил ни один из четырёх контрольных доменов, включая example.com. Прямой UDP DNS также не ответил; DNS over HTTPS через два публичных сервиса дал адреса. HTTPS по этим адресам, с сохранением исходного имени и проверкой TLS, вернул реальный HTML сайта. Это локальный сетевой дефект наблюдаемого подключения; переносить этот диагноз на знакомых пользователя пока нельзя. Системный DNS, hosts, VPN и настройки сети не менялись. Адрес задавался только для отдельного диагностического HTTP-запроса.

Выборочный поиск в app/c7, конфигурации Next и пакетировщике не нашёл localhost/127.0.0.1, IP allowlist, проверок forwarded IP или hostname. Экспорт статический; настройки Cloudflare/Harvis этим поиском не проверяются. Зарегистрированный в .openai/hosting.json Sites project вернул `Sites project not found`; текущие Harvis URL не управляются доступным Sites connector. Настройки другого проекта не менялись.

## Что не установлено

Привязка просмотра к IP автора **не подтверждается**: обе версии ответили 200 с четырёх других сетей. Не установлены точная неработающая ссылка, ошибка посетителя, его провайдер и этап отказа (DNS/TLS/HTTP/ресурсы/JS/WebGL). Поэтому никакое исправление доступа пока не заявляется. Код, публикация и адреса во время расследования не менялись.

У Harvis есть отдельный риск срока preview: [официальные условия анонимных публикаций](https://harvis.dev/about) описывают удаление через сутки без закрепления. Receipt v614 даёт срок до 01.11 07:28:42 МСК; v615 — до 01.11 08:07:19 МСК. Это не доказательство причины нынешнего отказа. Даже старый v600 в текущем запросе вернул 200 после заявленного срока; фактическое удаление по одному receipt не предполагается. Сохранение/обновление существующего адреса требует привязки к аккаунту или deployment credential согласно [HTTP/MCP-документации](https://harvis.dev/mcp); приватные значения не читались и не выводились.

## Следующий шаг

Получить точный URL и текст ошибки из уже заданного вопроса. Для DNS/соединения — одна целевая проверка из соответствующей сети; для 403 — настройки и поддержка хостинга; для пустой страницы — конкретный упавший ресурс/ошибка JS. Не менять сцену для исправления сетевой недоступности. Не выдавать новую ссылку как исправление прежней. Не обещать поддержку всех IP по четырём пробам.

## Реально выполнено

- Проверка двух публичных receipt и сравнение полученного HTML с архивами v614/v615.
- Обычный локальный DNS для четырёх доменов, два запроса UDP DNS, два HTTPS DNS сервиса; четыре HTTPS GET с публичным DNS и TLS.
- Один внешний HTTP-check на каждую последнюю версию с четырёх узлов; один запрос результата каждого check. Не нагрузочный тест.
- Чтение официальных страниц Harvis about, llms, MCP, terms и Check-Host API; чтение Sites SKILL.md и один get_site существующего проекта; выборочный поиск сетевых ограничений в исходниках.
- Новых сборок, публикаций, изменений продукта, окружения, зависимостей, секретов или локальных серверов нет.

Протоколы/ответы: `evidence/c7-architecture-speed-2026-10-31/public-access/`. Первый запрос справочника узлов с неверным Accept не дал JSON; исправлен на application/dns-json. Этот технический повтор не считается отказом сайта. Новые метрики производительности не измерялись.

# C7 v627 · план правок по фидбеку 04.11.2026

Задача пользователя (заменяет v626-FPS-план на этот проход):
1. Холмы зелёные, без чёрных точек (сильно бросается в глаза).
2. Солнце структурнее: круглое очертание диска, а не яркое пятно.
3. «Справа в углу при скроллинге что-то трясётся» (подтверждено фото к сообщению).
4. Сайт грузит долго, 3D при открытии — починить.

База: опубликованный v625 (commit `98746d0`, html `44ddc007…`). Ссылка прежняя:
https://maxkostxxx.github.io/c7/ . Вид работы: без агентов, без коммитов исходников,
сохранить незакоммиченные изменения (или сохранить себе).

## Диагностика (выполнена, все четыре механизма установлены)

1. **Чёрные точки на холмах** — НЕ атлас теней (эксперимент uSkyTreeStrength=0:
   1600→1623 спека, без изменения), НЕ фазовый радиус (v617-p1 на месте).
   НО: `hemi.intensity = .015*daylightEnergy` — полусферный свет на рассвете почти
   выключен; дальняя растительность/трава на холмах получает ~0 ambient и
   читается чёрными силуэтами-точками на зелёном. Днём (вертикальное солнце +
   high IBL) те же места гладкие.
   Цель: пол-ambient на рассвете, плавное выключение к solar .30.
2. **Солнце-пятно** — диск существует (solarCore .006 рад ≈ 14 px, ядро
   uSunColor(10,7,3.5)*1.2), но тонет: на рассвете aureole r=.030 рад яркостью
   (3.0,2.8,2.0) + outer-гало σ²=.0049 (≈160 px) + белое небо → весь верх
   насыщен 220+, профиль яркости плоский 221–227, диска не видно.
   Цель: сузить aureole (.022), ослабить outer (1.6,1.72,.62), усилить ядро
   (×1.5), чуть уменьшить диск (.0056). Dusk-ветвь микса не трогается.
3. **Тряска справа внизу** — парный захват фиксированной позы (about, solar .19):
   правый нижний угол меняется на 5.6% пикселей (>5/255) между одинаковыми
   кадрами; карта диффа: плотные изменения y=700–900 (ближняя трава) + полоса
   y=560–640 (far-grass). Причина: ветровая анимация травы
   (grass.js: uWind .65, gust .18, flutter .035; far-grass.js: uWind .45).
   На фоне яркой засветки это читается как «трясётся».
   Цель: снизить амплитуду ветра (near .65→.40, flutter .035→.02, gust .18→.12;
   far .45→.28), тайминги сохранить.
4. **Долгая загрузка** — v625: локально Chromium 390 = 2.15 s, 1440 = 3.0 s; при
   контролируемой сети 4 Mbps/100 ms = **6.29 s** (это и есть ощущение
   пользователя). Состав передачи: страница+чанки ~0.56 MB decoded, постеры
   ~60–120 KB, runtime: world.js 836 KB + geometry/fields загружаются worker'ом
   ПОСЛЕ старта worker (серийно относительно HTML/чанков).
   Цель: <link rel="prefetch"> на world.js (и worker-entry.js/startup-inputs.js)
   в HTML — параллельно с загрузкой страницы; worker потом читает из HTTP-кэша.
   Ожидание: на 4 Mbps ready сокращается примерно на время передачи world.js
   (≈1.6–1.7 s) за вычетом конкуренции.

## Гейты

- Fixed-pose пары (v625 vs v627, same pose через route-fulfill):
  зоны «вне правок» (небо-без-солнца, terrain при dusk, деревья) ≈ 0 diff;
  зоны правок (диск, холмы, трава) — ожидаемые измеримые диффы.
  Dusk-идентичность прямых читаемых полей (всё, кроме солнца и травы) ≤ .3/255.
- Спеки на зелёных холмах (локально-контрастный счётчик): заметное снижение.
- Ветер: дифф-карта фиксированной позы правого нижнего угла: плотность
  изменений падает в разы.
- Startup: ready при CDP 4 Mbps/100 ms mobile и desktop: v627 < v625 (цель: минус
  1+ s mobile); локальный cold ready не хуже.
- Живой браузер + check-host + статические ссылки; скриншоты ДО/ПОСЛЕ для
  пользователя (герой: холмы/солнце; about: правый нижний угол).

## Риски

- hemi-пол поднимает ambient всего рассвета (арт-изменение по запросу
  пользователя; калибровка dawn-look меняется — принимается пользователем).
- Солнечные правки действуют весь день (uSunDusk=0) — дневное солнце тоже станет
  структурнее (пользователь просил «структурировать солнце»).
- prefetch добавляет до 836 KB к начальной загрузке (конкуренция с постерами,
  у которых fetchPriority=low) — проверяем на контролируемой сети.
- v626-FPS-план не трогаем (отдельный проход), нумерацию не занимаем.

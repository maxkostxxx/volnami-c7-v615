# C7 v604 — точное ускорение подготовки рельефа

Тестовая ссылка: https://quiet-pebble-339.harvis.page/c7/. Публикация 30.10.2026,03:46МСК; по receipt доступна до31.10.2026,03:46:33МСК. Старые preview v601/v603 сохранены.

Следующая контрольная версия после v603. Сложная сцена, камера, свет, трава, тени, отражения и DPR сохранены. Изменения касаются повторных вычислений при подготовке terrain; художественных правок в этом выпуске нет.

## Результат

В парном тесте полного сайта ABBA готовность сократилась с 4417/4377 до 3875/3875 мс: среднее **4,397 → 3,875 с, −11,87% относительно v603**. Chromium 153 / ANGLE Metal / Apple M3 Pro, viewport 1440×900, drawing buffer 2160×1350, normal, свежие browser contexts, локальный HTTP. Во всех повторах действительно использованы terrain cache и startup cache. Это локальная готовность первого render submission, не время первого показа на дисплее или обещание скорости по мобильной сети.

Сам модуль рельефа в CPU-only browser ABBA готовился за 1279/1254,5 → 802,7/795,6 мс, около −37%. На кадр это не повлияло: active submitted 36,753 → 36,492/с, main rAF 47,656 → 47,942 Гц. Кадровое ускорение не заявляется.

## Удалённая работа

- Вспомогательный профиль левого склона строил 41 узел, хотя следующему этапу нужны высота плеча и касательная, определяемая тремя соседними узлами. Теперь считаются только эти три узла с прежней арифметикой; итоговый профиль остаётся полным.
- Четыре итерационных сглаживания больше не копируют исходный массив на каждой итерации и не обходят неактивные точки. Оба буфера инициализируются один раз, все активные внутренние точки обновляются в прежнем порядке. Неактивные точки остаются исходными.
- Интерполяция неизменяемого гребня повторялась для одного X при множестве разных Z. Теперь хранится только последнее значение X и четыре Float64 для каждого внутреннего гребня. Это ограниченное переиспользование, без растущего пространственного кэша; знак нуля учитывается.

Вместо удаления расчётов рассматривался дополнительный точный файл полей. Простое сжатое представление потребовало около4МБ и было отклонено. Принятый вариант не добавляет бинарные или графические ресурсы: runtime вырос лишь на1365байт текста, до **6 554 209байт / 54файла**.

У списка активных точек есть временная цена памяти: 648720байт суммарных выделений в четырёх генераторах, максимум193596байт для одного списка. Это не resident GPU peak. Удалённые копирования массивов — экономия повторных записей, а не такое же сокращение выделенной памяти.

## Почему прежние данные остаются корректными

Все десять вычисленных полей совпали. Помимо структуры и полных typed-array hashes отдельно проверены **882916 численных компонентов как Float64, включая −0**, в Node и Chromium. Также совпали100000 компонентов высоты, расстояния до берега и нормалей на20000 детерминированных точках.

Terrain/sky/startup payload не пересоздавались и сохранили SHA. Обновлены только метаданные зависимости от terrain.js и закреплённый hash startup manifest. Основание — полная эквивалентность полей и неизменность остальных формул, зафиксированные в `terrain-cache-validity-proof.json`. Упаковщик продолжает отвергать неизвестный source. Старый runtime-v603 не изменён.

## Новые проверки

Все пути evidence находятся в `evidence/c7-overnight-2026-10-30/`.

- `terrain-field-cpu/`: отдельные кандидаты, Node/browser ABBA, структурная и численная эквивалентность.
- `terrain-pixels`, `terrain-pixels-responsive`: **34/34** точных межверсионных raw pixel пар на390/1440/2560, включая обратный пролёт.

- `terrain-lifecycle-results.json`: restore точен; повреждённый startup cache корректно возвращается к генератору с тем же кадром; abort освобождает контекст; dispose освобождает геометрию.

- `build-v604-retry-2g.log`: JS, TypeScript и static export прошли; `out/c7-build.json` подтверждает текущие source SHA. Все113 файлов итогового архива совпадают с испытанным пакетом.

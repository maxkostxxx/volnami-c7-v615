# C7 v607: проверенный проход ускорения старта

30.10.2026. План: [c7-speed-plan-after-v606-2026-10-30.md](c7-speed-plan-after-v606-2026-10-30.md). Исполнитель один, без агентов; браузеры headless, GPU-проверки последовательны. Предыдущая v606 и её пакет сохранены, коммитов нет.

## Результат и границы результата

Ускорена подготовка первого живого кадра. В парном Chromium-тесте с задержкой сети 100 ms и пропускной способностью 10 Mbit/s: **8,958 → 8,535 s**, выигрыш **423 ms / 4,72%**. Это контролируемая лабораторная сеть, не измерение соединения пользователя. «Моментальная загрузка» и существенное ускорение пролёта **не достигнуты**.

Изображение выбранного изменения сохранилось: **23/23 raw pixel-пары** на 390/1440/2560, одинаковые SHA скомпилированных шейдеров, draw/triangle/memory counters; **6/6 возвратов** к началу точны после согласованного прогрева. Это конечная выборка состояний, не доказательство совпадения с исходным художественным референсом. Рассветная правка деревьев v606 сохранена.

## Что изменено

1. **Независимые загрузки перестали ждать друг друга.** `lab/c7-scene/world.js:128`: облака, текстуры деревьев, рельеф и уже существующие horizon/startup transfers могут загружаться одновременно. Прежний порядок ждал облаков перед рельефом, а текстуры деревьев запрашивал только после рельефа и материала. Готовность облаков теперь проверяется перед загрузкой GPU-текстур и первым PMREM (`world.js:414`). Первый живой кадр по-прежнему содержит все ресурсы.
2. **Явное владение ранними текстурами.** `trees.js:403,431,652`: один подготовленный набор передаётся одному генератору. Повторный consumer запрещён; незабранные и частично загруженные текстуры освобождаются при ошибке/отмене. Worker fetch принимает AbortSignal (`canvas-platform.js:3`). Для DOM ImageLoader отмена освобождает поздний результат; транспорт самого HTML-изображения этим API не прерывается.
3. **Повторные преобразования данных освещения заменены точной таблицей.** `sky-horizon.js:42`: значения Int16 имеют конечное множество. Для каждого масштаба таблица вычисляется тем же `T.DataUtils.toHalfFloat`, затем миллионы значений выбирают готовый результат. Восстановленные оба поля проходят прежние встроенные SHA. На один текущий field выделяется 256 KiB таблиц, суммарно на два декодирования 512 KiB; они не сохраняются в GPU-текстурах. Это оценка выделенных таблиц, не resident-memory peak.

Удалена часть последовательного ожидания сети и повторная арифметика конвертации. Не исчезли загрузка тех же ресурсов, процедурная сборка травы/деревьев, компиляция, карты теней, PMREM, отражение и основной рендер. Никакого нового прохода кадра не добавлено.

**Геометрия, плотность травы, DPR, шейдерные формулы, текстуры, terrain/sky/startup binary caches и постеры v606 не менялись.** Кэши не пересоздавались. Runtime вырос на 3 040 B кода: 6 554 774 → 6 557 814 B raw. Это ускорение старта, а не очередное уменьшение сетевого веса.

## Что отклонено

До изменения продукта проверены два варианта травы: более узкие границы существующих 5 m участков и ранний vertex-return для полностью исчезнувших травинок. Это не уменьшение плотности и не объединение patches. Завершение 48 изменяющихся кадров измерялось через `readPixels`, после 24 кадров прогрева; порядок baseline/bounds/early/early/bounds/baseline, по три пакета.

Границы дали лишь около 3%, ранний выход — практически ничего. Оба не прошли строгую pixel-проверку и заранее заданный ≥8% performance gate. **В продукт не перенесены.** Сами различия не объявлены заметной визуальной порчей: их художественная оценка не проводилась, поскольку speed gate уже не пройден. Старый PCF-skip не повторялся.

Отдельный последний кандидат проверял новую причину: sky samples1/3 имеют одинаковый azimuth5/3° и читают одинаковый horizon field, хотя их elevation/visibility различаются. В отличие от старого reuse между двумя ground lobes, повторное использование здесь распространялось между источниками и на траву. Это убирало часть texture fetch, но добавляло состояние fragment shader. Baseline607/candidate ABBA: **1425,82 → 1444,73 ms** за завершённые48кадров, то есть **на1,33% медленнее**.22/22 pixel-пары точны. NO_GO, shader-кандидат остался только в evidence; source/code v607 не менялся. Доказывать реальное уменьшение стоимости надо измерением, а не числом удалённых строк/fetch.

## Приоритет следующего прохода

1. Принятый путь старта — одновременная подготовка обязательных ресурсов с прежним первым кадром. Он уже реализован; добавлять мегабайты подготовленных данных ради десятков миллисекунд не предлагается.
2. Для плавности сначала нужен новый доказанный механизм удаления GPU-работы. После двух неудачных grass-проб нельзя обещать большой выигрыш точечными правками. Следующая ограниченная диагностика: при фиксированных камере, drawing buffer и изменяющемся solar сравнить завершённые пакеты с разным покрытием main fragments, сохраняя vertex submission и остальные проходы. Scissor используется только как диагностический фактор, не переносится в продукт. Такой тест показывает чувствительность к pixel work, но не точную эксклюзивную стоимость проходов.
3. Архитектурный кандидат должен сначала доказать удаление старой работы и сохранение её потребителей: основной вид, отражение, свет и тени. Простое добавление resolve/light buffer поверх прежних расчётов не принимается. До результата диагностического gate конкретная дорогая переработка не объявлена полезной. G07 остаётся REWORK.

Не возвращать без новой причины: снижение качества, прежний PCF skip, ground-field reuse между двумя lobes, wind lattice, дополнительные grass depth/radiance/resolve passes, 17 PMREM maps, старый CPU terrain occlusion и отвергнутый low-sky transport. Одного сходства идеи с оптимизацией недостаточно.

## Реально выполненные проверки

- Исходный checkpoint и проверка baseline runtime; tracked diff SHA `cca8bbcb1a9932b74371aa1940a9f430f9084327c60546c7448365c541273f4d` сохранён.
- Новые frame probes, один startup stage/resource profile, один Node CPU terrain profile; они не выдаются за старые тесты и наоборот.
- Один новый shared-azimuth shader ABBA после сборки607; точные пиксели, отрицательный speed result (`azimuth-results.json`, `azimuth-decision.json`).
- ABBA загрузки: сначала overlap-only, затем финальный overlap+decoder+cancel. Результаты разделены (`startup-abba.json`, `startup-final-abba.json`).
- 46 responsive raw кадров /23 межверсионные пары и6 reverse pairs, без GL/console/page errors. Новый desktop hero открыт визуально.
- 6 lifecycle-сценариев: ownership, concurrent double claim, dispose while pending, один404, worker fetch abort, world abort while cloud pending — PASS.
- Полный сайт ABBA в worker, без steady shader compilation. Локальный portable607: Chromium390/1440/2560 load/flight/solar/reverse PASS; Firefox1440 и headless WebKit1440 — функциональный PASS.
- Сборка1536MiB завершилась SIGKILL; повтор1024MiB прошёл. Только process-local параметры, без изменений зависимостей/общих настроек и без удаления общих кэшей. Manifest экспорта82источника проверен.
